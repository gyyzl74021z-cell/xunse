# B 的 Lab 矫正 Demo 对接核对说明

核对日期：2026-11-07

## 1. 核对范围与结论

用户提供的 `Lab矫正Demo.zip` 仅包含 `lab_correct.py` 和 `test.jpg`。这是 Python + OpenCV 的 PC 静态图片演示。Android 现有设置模块已覆盖该 Demo 所需的模式、强度和独立矫正开关；本次没有修改 Android 工程，也没有将 Python 算法接入 Android。

压缩包 SHA-256：`29715c081ad7abca33cedc04c20376d907ff2844d9afcbc98a99c6820a1bc20c`

## 2. 参数映射

| 参数 | B 的实际代码 | Android 现有约定 | 结论 |
| --- | --- | --- | --- |
| 色弱模式 | `mode=0` 为 Protan，`mode=1` 为 Deutan；分别对 Lab a 通道减、加强度乘以 18 | 红色弱为 0，绿色弱为 1 | 两种已定义模式一致 |
| 矫正强度 | 滑块 0–30，除以 10 后得到 0.0–3.0，步长 0.1 | 存储整数 0–30，`toLabParams()` 除以 10 | 一致 |
| 强度默认值 | 演示滑块初始值为 10，即 1.0；函数签名默认值为 1.2 | 初始值 10，即 1.0 | 后续调用显式传入用户设置值，不依赖函数默认值 |
| 矫正开关 | 在主循环外层判断；0 直接使用原图，1 调用矫正函数 | `correctionEnabled` 单独存储并导出为 0/1 | 参数含义一致；接入时保留独立开关 |
| 首次开关状态 | Demo 初始开启 | APP 初始关闭 | 当前为不同的产品默认值，未自动修改；需要统一时由团队确定 |
| 图像通道顺序 | 函数接收 BGR，输出 BGR；内部使用 OpenCV 的 8 位 Lab 表示 | Android 目前仅保存参数，没有图像处理接口 | 后续接入先明确相机/位图的 RGB、RGBA 或 YUV 转换，不能直接混用 |

目前只实现红色弱、绿色弱两种模式，没有蓝黄色弱实现。`mode` 非 0 的值都会走绿色弱分支，因此调用端只传 0 或 1。

## 3. 基础运行核对

使用已有项目虚拟环境运行，无安装或升级依赖：OpenCV 4.10.0，NumPy 1.26.4。通过导入源码调用函数，没有启动桌面窗口或相机。

- 附带图片正常解码：400 × 268，三通道。
- 两种模式分别检查强度 0.0、1.0、3.0，共 6 组，均正常返回，输出尺寸和 uint8 类型正确。
- 该检查仅证明这些输入下函数执行正常，不代表已验证色弱用户的实际辨色改善效果。
- 强度 0 仍经过 BGR/Lab 往返转换，存在小幅像素舍入差异。需要严格原图时，应使用独立开关跳过矫正函数。
- 未验收 Demo 的桌面交互，也未验收 Android 上的图像处理、实时性能或设备运行效果。
